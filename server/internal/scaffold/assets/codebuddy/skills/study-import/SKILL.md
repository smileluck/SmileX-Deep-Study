# 学习材料导入（W1）

你是学习系统的导入 agent。

**第一步：读取 `roles/librarian.md` 并全程保持「导入员」人格**（忠实提取、原子笔记、制卡质量、零状态建卡四条铁律）。
**第二步：完整阅读仓库根目录 `AGENTS.md`（数据契约，必须严格遵守）。**

然后按以下步骤执行：

1. **解析材料**：读取 `data/inbox/` 中用户指定的文件。**PDF 优先调服务端接口提取文本层**：`curl -s "http://127.0.0.1:5574/api/materials/extract-text?name=<文件名>"`（随二进制分发，零安装；加密 PDF 自动尝试空密码解密）。返回 `text` 为空/近空说明是**扫描件**：**按文末「扫描件（视觉转写）标准流程」一节处理**（PyMuPDF 渲染 → 主线程不读图、派并行子代理逐字转写落盘 → 按单元号合并去重），不要凭推测补写。DOCX/EPUB 等用你可用的解析能力提取文本；提取失败就按角色纪律如实报告并中止。**若参数是 http(s) URL**：用你自带的网页抓取能力（如 FetchURL）抓取并理解正文（避开导航/广告等噪声），将正文整理为 markdown 写入 `data/inbox/<kebab-标题>.md` 作为归档原件，随后按普通文件流程继续；抓取失败（登录墙、纯 JS 渲染、反爬）或你没有抓取能力时如实报告并中止，不许编造内容。
2. **确定主题**：用户给了 topic-slug 就用；否则根据材料内容起一个 kebab-case slug，在 `data/topics/<slug>/manifest.json` 建主题（字段：slug/name/goal/created/description，goal 可先留空问用户）。**slug 已存在则复用 manifest**：不重建、不改 goal（description 如需补充可更新），多个材料可陆续导入同一主题。
3. **归档材料**：把文件移动到 `data/library/`，重命名为 `<materials.json 当前最大 id + 1>-<原文件名>`；在 `data/library/materials.json` 数组**追加** `{id, original_name, stored_name, topic, status: "imported", imported_at: <今天>}`。网页导入时 `original_name` 记原始 URL，`stored_name` 为转存的 md 文件名。
4. **写原子笔记**：通读材料后先梳理概念的学习依赖顺序（先修概念在前），按该顺序为每篇笔记分配 `order`（frontmatter 字段，主题内从 1 递增；追加导入已有主题时默认从该主题现有 max(order) 续排）。为材料中每个值得学的独立概念写一篇 `data/notes/<kebab-id>.md`（按角色纪律：自己的话重组、原子化、带 links）。**顺序调整**：若追加导入的新概念是某些现有笔记的先修（更基础），不要机械续排在末尾——将其插入对应位置，受影响现有笔记的 `order` 顺延重排，保持主题内唯一递增；`order` 只是排序键，改动不影响卡片与复习状态；重排结果记入会话日志。
5. **概念去重（追加导入已有主题时必做，在写笔记前执行）**：先读该主题现有全部笔记（`data/notes/` 中 `topic` 等于该 slug 的笔记，看 title 与正文要点），把材料中梳理出的概念与之一一比对：
   - **已覆盖**：现有笔记已讲清该概念 → 不新建。若新材料带来增量（更清晰的阐述、新例子、修正），把增量合并进现有笔记正文（保持原子结构与"自己的话"风格，可按需补充 `links`）；`id`/`order`/`created`/`source` 字段不动。
   - **部分重叠**：材料讲的是该概念的新侧面 → 为真正的新概念写新笔记，与已有笔记通过 `links` 互链。
   - **全新概念**：正常新建笔记。
6. **起草卡片**：每篇笔记 2-5 张 `data/cards/<note-id>-cN.md`，质量标准见角色铁律 3；每张卡必须写 `hint`（15-40 字回忆抓手，只给思考方向，不给答案）；frontmatter 的 `fsrs:` 块原样复制 AGENTS.md 的全零模板。合并过的笔记只针对增量内容补卡，先检查该笔记已有卡片避免题面重复。
7. **写会话日志**：`data/sessions/YYYYMMDD-import-<topic>.md`（type: import），正文记录去重比对结果（哪些概念合并进了哪篇现有笔记、哪些跳过），并在 `data/progress/mastery.json` 为该 topic 新建条目（level 0，evidence 记 kind: import；主题已有条目则不重建）。
8. **收尾自检（必须）**：执行 `curl -s http://127.0.0.1:5574/api/validate`——`errors` 必须清零；有错就修复后重跑，直到干净。
9. **报告**：列出新建/更新的全部文件 + 校验结果，提醒用户到 Web UI（默认 http://127.0.0.1:5574）查看到期队列开始复习。

## 已知坑（会直接导致校验不过，务必先看）

1. **`fsrs.due` 必须加双引号**。写成 `due: 2026-09-14T00:00:00Z`（裸标量）时 YAML 会解析成时间对象，而服务端 `normalizeTimes` 对"零点整"的时间会降级成纯日期 `2026-09-14`，随后 `fsrsx.FromMap` 报 `fsrs 块格式错误: parsing time "2026-09-14" as ...`。正确写法：`due: "2026-09-14T00:00:00Z"`。
2. **frontmatter 里的标题/值只要以 `"` 开头或含 ASCII `: `，就必须整体加引号**。例：`title: "四基"课程目标：…` 会让 YAML 在第 1 行报 `did not find expected key`。写成 `title: '"四基"课程目标：…'`（单引号包裹，内部单引号需双写）。
3. **批量产出建议用一次性脚本**。材料较大时（几十篇笔记 + 几十张卡）逐文件手写既慢又容易漏字段；用 Python 把 `NOTES` 数据结构一次性落盘，再统一跑校验。落盘后仍要执行第 7 步。
4. **frontmatter 的字符串值是 YAML 双引号标量——值里不能出现反斜杠！** `title: "接近理想的低通网络：$R=\sqrt{L/C}$ 的电路实例"` 会让 YAML 在 `\s` 处报 `found unknown escape character`，`/api/validate` 直接 `ok:false`（第五章导入时真实翻车）。**`title`/`tags`/`links` 一律不写 LaTeX 反斜杠**，改用 Unicode（`√(L/C)`、`H(jω)`、`0⁻`、`Sa`）或改写措辞；**正文 body 不受影响，LaTeX 照写**。构建脚本加断言 `if "\\" in id+title+tags+links: raise` 前置拦截，比事后修文件省事。
5. **`hint` 长度按 17–22 字写，别按 15 字下限写**。中文标点也计 1 字，凭感觉写短抓手时极易落在 10–14 字：实测返工比率分别为 17/107、69/113、83/124，下册第七章降到 5/112（按 17–22 字写有效），**第八章反弹到 100/156**（本批以"口诀式"提示为主，`一个抬高，一个压低` 只有 9 字），**第九章回到 20/184**（全部卡在 13–14 字）。**结论：按 17–22 字写是有效的，但口诀必须当场补成完整句（≥17 字）**。两条对策：① 写卡当下就把 hint 写足；② **修复脚本加保险丝**——`while len(h) < 15: h += "，想清楚再答"`，一次跑完不返工，并在修复后用 `scan_hints.py` 复扫确认 0 越界（**这一步不要因"这次写得长"而跳过**）。另注意 `hint` 按 AGENTS.md 应是**思考方向**而非答案原文，补词时顺手把泄底提示改成方向提示。
6. **数据模块必须分片 Write**。一次 Write 一个大 `NOTES`/`CARDS` 文件会被截断（内容写到一半就断）。按 order 每片 10–12 篇拆成 `chN_notes_p1/p2/p3.py`、`chN_cards_p1/p2/p3.py`，构建脚本 `NOTES = NOTES1+NOTES2+NOTES3` 合并。
7. **追加导入（同主题第二批起）用"数据模块 + 构建脚本"分离**：构建脚本只补 notes/cards + mastery evidence + 新会话日志，**不重建 manifest、不追加 materials、不动 inbox**（manifest 仅可更新 `description`，不改 `goal`）。脚本要幂等：笔记 id 若命中既有文件，读前 400 字符验 `topic:`——同主题视为幂等覆盖，他主题必须报错；mastery evidence 按 `detail` 全文查重后再追加。校验用 `python -W error::SyntaxWarning` 可一次扫净正文里的单反斜杠隐患。
8. **⚠️ 绝不用 bash heredoc 写含反斜杠的脚本**。`cat > x.py <<'PYEOF' … PYEOF`（**即使加引号防变量展开也没用**）会把脚本里的 `\s`、`\d`、`\b` 静默改写成 `/s`、`/d`、`/b`，于是正则永不匹配、脚本 exit 0 但结果为空——第六章批次因此白跑两轮（扫 358 个笔记找 `topic:\s*"…"` 返回 0 条，还以为数据有问题）。**凡脚本含正则或任何反斜杠，一律用 Write 工具落盘 `.py` 再执行**（Write 写的文件反斜杠完好，已验证）。
9. **`re.match` 锚定行首，扫「字典行内字段」要用 `re.search`**。卡片数据模块里 id 行形如 `    {"id": "xxx", "note": …`，行首是 `{`，所以 `re.match(r'"id":…')` 永远不匹配，批量替换脚本会报告 `changed=0`。**排查口诀：批量替换脚本报 0 处修改时，先怀疑 match/search 与锚点。**（`^(\s*)"hint":` 这类确实从行首开始的字段，用 `match` 才对。）
10. **卡片的 `front` / `hint` 是 YAML 双引号标量——同样不能出现 LaTeX 反斜杠**（第 4 条只管笔记 frontmatter，卡片是另一个入口）。写成 `front: "求 $\dfrac{E}{a+j\omega}$ 的逆变换"` 会让 `/api/validate` 报 `frontmatter 不是合法 YAML: found unknown escape character`。**对策：卡片 front/back/hint 一律用 Unicode 纯文本数学，与既有卡片保持一致**——`δ(t)`、`1/(s+a)`、`s²+ω²`、`e^{−at}`、`|ω|<ω_c`、`Σ`、`∫₀^y`。`back` 虽然是 `|` 块标量（反斜杠安全），也照样写纯文本，因为 Web UI 把它当纯文本渲染，LaTeX 只会显示成裸代码。构建/修复脚本加断言 `if "\\" in front+back+hint: raise`。
11. **Python 数据模块里 `'''` 会截断 `r'''…'''` 原始字符串**。写三阶导数时 `$v_o'''+\ldots$` 会提前终止字符串字面量，落盘后脚本 `SyntaxError: invalid decimal literal`。**对策：LaTeX 阶数改写 `^{\prime}` / `^{\prime\prime}`（顺带比光秃秃的撇号更清晰）**；同理不要把 `"""`、`'''` 直接写进 body。**落盘数据模块后先 `python -X utf8 -m py_compile <file>` 预检**，别等构建脚本报错才发现。
12. **沙箱下 `curl` 调本机服务可能返回空**：`curl -s -m 20 -o out.json -w '%{http_code}' http://127.0.0.1:5574/api/validate` 可能给出 `http_code=200 size=0`、`curl exit=23`（写文件失败），看着像服务端挂了。**改用 Python `urllib.request.urlopen` 直连读 JSON，结果正常**（本批就用它拿到 `ok:true`）。另：服务端进程若被中断，用 `run_in_background` 重启 `./deep-study.exe`，日志在 `.workbuddy/server.log`；`netstat | grep 127.0.0.1:5574` 确认在听。
13. **磁盘吃紧时先清渲染缓存**：扫件批次累计的 `.workbuddy/pdf_pages_*/` 动辄 50 MB+（390 页 ≈ 52 MB）。已导入并完成转写的章节页面可删（PDF 在 `data/library/`，可随时再生）；`df -h` 先看余量，D 盘见底会直接让构建写文件失败。**删渲染页时别用 `awk -F'p'` 之类按路径字符切分页码**——路径本身含 `p`（`pdf_pages_...`），字段会错位把整批删掉；用 Python 按 `os.path.basename` 解析数字。
14. **反向 `links` 回填是追加导入的必备步骤**。追加时新笔记常与既有笔记"概念对位但内容不重复"（典型：连续版 ↔ 离散版、上册 ↔ 下册）。除了在新笔记里链过去，还要在**旧笔记**的 `links` 里补回新 id，否则知识网是单向的。做法固化为一组 `REVERSE_LINKS = [(旧id, 新id), …]`：`re.search(r"^links:\s*(\[[^\]]*\])\s*$", txt, re.M)` 取旧数组 → `json.loads` → 去重后 append → 用 `json.dumps(arr, ensure_ascii=False)` 写回。**`json.dumps` 默认逗号后带空格，与既有笔记格式一致**；只改 `links` 行，命中即跳过，天然幂等。反填清单记入会话日志与 mastery evidence。
15. **公式辨析要用 900 DPI 局部裁切，不要停在 420 DPI**。`page.get_pixmap(dpi=420, clip=pymupdf.Rect(...))` 能定位，但小字号处的"少一个字母 / 多一个 π"仍会误判（真实案例：`e^{j(n/8−π)}` 被转写成 `e^{j(π/6−π)}`，分子错且漏 `n`，直接影响"是否周期序列"的结论）。**两级做法：420 DPI 先框出大致区域 → 把 `clip` 收窄到页面宽 15%–40% → 900 DPI 再拍一张确认。** 另：重叠区机械比对（`difflib.SequenceMatcher` 逐页 diff）也可能给出**零分歧**的正面结论（下册第七章 p024/p025 字节级一致、第八章 14 个重叠页零分歧），这是"确认无误"而非"没认真比对"，照常记录进会话日志。**比对前先把排版差异归一化掉**（去 `\left`/`\big`、统一全半角括号、`\sum\limits`→`\sum`、去 `=` 两侧空格、去 `[Npt]`、去页眉标注），否则真实分歧会淹没在噪声里——第八章第一版 diff 全是排版噪声，归一化后立刻干净。
    - **diff 仍看不出结论时，换「结构化元素集合」做硬判据**：第九章 65 页的重叠区（p143–p147、p162–p166）用归一化 diff 依然被截断窗口与记法差异淹没。改用**比对重叠页里出现的「编号公式编号」集合**（`\tag{9-xx}`）后一次干净：9-1～9-137 无缺号、各重叠页编号集合完全一致。**口诀：互校看不出结论时别硬啃 diff，改成"编号 / 表行数 / 小节标题是否相等"这种不因排版而变的集合判据。** 第十章 20 个重叠页（p205–p209、p222–p226、p240–p244、p258–p262）同样靠它给出干净结论：逐页编号集合全部一致、全章 10-1～10-169 无缺号——**行级 diff 的 ratio 在 0.36–0.97 之间乱跳，完全不能用来下结论。** 脚本可直接复用 `.workbuddy/xcheck_<ch>_tags.py`。
16. **`links` 里凭记忆写概念名必悬空——落盘后必须机械核对**。第八章批凭印象写了 `s-plane-geometry`、`rlc-resonance`、`system-function-Hs`、`time-shifting-property`、`laplace-transform-definition`、`typical-signal-laplace-transforms`、`all-pass-filter`、`frequency-convolution-theorem` 等 **14 个**，全部不存在（真实 id 是 `s-plane-geometric-analysis`、`second-order-and-resonant-system`、`system-function-definition`、`laplace-property-time-shift`、`laplace-transform-definition-convergence`、`laplace-transform-table`、`all-pass-function`、`convolution-theorem` …）。**`/api/validate` 不报这个**（links 是自由文本），只能自己查。四个动作：
    - 写 `check_links_<ch>.py`（**必须用 Write 落盘**，别用 heredoc）：`import` 本批 NOTES → 对每条 link 判断「在本批新 id 集合内 或 `data/notes/<id>.md` 存在」→ 打印悬空清单，修完复跑确认 0；
    - 修正用**带引号的精确替换** `s.replace('"old"', '"new"')`，否则 `laplace-transform-definition` 会把 `...-convergence` 一起改坏；
    - **构建脚本里加断言**：links 目标必须存在，否则 `fail()`——以后不必事后补；
    - 找真实 id 的快捷路径：先跑 `list_topic_notes.py` 导出全主题 id 到文件，再 `grep -iE "关键词"`，比逐个猜快得多。
17. **`front` 全局查重必须排除"自身文件"，否则幂等重跑误报**。构建脚本加 front 查重后，重跑时报 156 处"重复"——命中的 `<id>.md` 正是本卡片自己的文件。正确写法：`if fronts.get(front) == card_id + ".md": continue`。
    - **但查重报出来的重复要人工判定，别机械删卡**：第九章批 `dft-parseval-theorem-c3` 的 front「帕塞瓦尔定理的物理意义是什么？」与第六章既有 `parseval-theorem-vector-space-c2` 字面完全相同，可答案一个是"各正交分量功率之和 / 完备性"、一个是"DFT 能量守恒"——**是两道不同的题**。正确处置是**把新卡的题干限定到自己的语境**（改成「DFT 的帕塞瓦尔定理说明了什么？」），而不是删卡或改既有卡。
18. **第 8 条的适用范围要扩到"一切内联脚本"**：不只是 heredoc，`python -c "…\"…\"…"` 同样会吞反斜杠。第八章批用内联脚本统计卡片数，`'topic: \"signals-and-systems\"'` 被吞后脚本安静返回"卡片 = 0"。**判据：内联脚本结果异常（空列表 / 0 匹配）时，第一反应就该是"反斜杠被吞了"，改写成 .py 文件重跑。**
19. **卡片数据模块落盘前的两个廉价预检**（能省一轮构建报错）：

32. **公式渲染体检：GFM 表格会吃掉数学里的 `|`，这是"笔记格式错误、渲染不对"最常见的一类**（本项目已中招 **22 篇 / 74 处**）。
    - **症状**：整行表格错位、公式被拆成几段、或以字面 `$...$` 原样显示（**不是红字**，而是裸文本）。根因是**列拆分发生在行内解析之前**：行里每个未转义 `|` 都被 GFM 当列分隔符 → 公式被切断、`$` 落单；更糟的是该行**格子数多于表头时多出的格子会被直接丢弃**（内容静默丢失）。
    - **三处典型触发点**：① 收敛域 `$|z|>|a|$`、`$|z|<1$`；② 绝对值 `$\left|F_n\right|$`、`$|H(\mathrm{j}\omega)|$`、`$|\alpha I-A|$`、`$|x(n)|^2$`；③ 取条件值 `$H(s)\big|_{s=\mathrm{j}\omega}$`、`$F_0(\omega)|_{\omega=n\omega_1}$`。**表头行同样中招**——表头里写 `对 $|H_a(\mathrm{j}\Omega)|$ 的约束` 会让表头本身变成 5 列，整表错位。
    - **修法**：表格行内数学区间的裸 `|` 一律换 `\vert`（KaTeX 等价，且不含 `|` 字符）。**必须写成 `\vert ` 带尾随空格**，否则 `$|H_a|$` → `\vertH_a` 会被当成控制字 `\vertH` 而报 undefined control sequence（本次实测踩到并回滚重做）。数学区间**之外**、两侧紧贴非空白的 `|`（如 `ln|x|`、`E(|X|)`）按 GFM 规范转义成 `\|`。**真正的列分隔符在本项目一律写成 ` | `（两侧空格），据此区分，别误伤。**
    - **数据行格子数确实多于表头**（内容里真多写了一列，如 `ch4-exercises-overview` 的"要点"列）时，把表头与分隔行补到该表最大列数即可，GFM 会给少格子的行自动补空。**先排除 ①/② 再动表头**——本次曾把 5 行"数学外裸 `|`"误判成"多一列"而错误加宽表头，靠人工复核才发现。
    - **导入后必跑体检**：`node .agents/skills/study-import/scripts/check_math_render.mjs <topic>`。它**复刻 Web 端真实渲染链路**（`normalizeDisplayMath` 与 `MarkdownInner.tsx` 逐字一致 → remark-parse + **remark-gfm** + remark-math → 每个 math 节点跑 `katex.renderToString`，并用 rehype-katex 实际解析到的那份 katex），报三类问题：① KaTeX 渲染失败（页面上是红字）；② 残留字面 `$`；③ 表格「格子多于表头」。**退出码非 0 即有问题**。配套 `scripts/fix_table_pipes.py <topic> [--apply] [--widen]`（默认 DRY-RUN，`--widen` 才动表头）。
    - **两个反面教训**：**(a)** 别只查"`$` 是否成对"——被拆坏的行里 `$` 仍分布在不同格子里、局部看是成对的；**(b)** 别只看 KaTeX 报错——本次 74 处表格问题 KaTeX **一处都不报**。**必须按"渲染链路的真实解析结果"体检**，而不是靠文本模式的直觉。

36. **小批量（<15 页）位图件由主线程直接读图即可，不必分段派子代理；但必须把「没有第二份独立转写可互校」写进核对记录**。本批 9 页由主线程 200 DPI 整页渲染后逐页读完（主模型的图片读取能力可直接用），再对 12 处易混公式做 500–900 DPI 局部裁切复核。这样省掉了分段/合并/互校的全套开销，但**代价是失去了唯一的自证手段**——质量控制只剩「高 DPI 回原页」一条。**做法**：在核对记录笔记里显式写出这一可信度边界（说明它与扫描件章节批次的差别），不要让读者误以为做过重叠互校。

37. **材料的章号体系与主教材不同时，先做一张「材料章 → 主教材章 → 本主题速查笔记」对照表，再动手写笔记**。本批材料是自考型编排：第一～四章分别是 信号分析的理论基础 / 傅里叶变换 / 拉普拉斯变换 / Z 变换，然后**连续域三个域并成「第六～八章」、离散域两个域并成「第九、十章」，且没有第五章**——与郑君里逐章展开的章号完全对不上。不建对照表就按「第 N 章」直接写笔记，会与新主题既有笔记的 `order`/标签体系打架，读者也无法把材料章号定位到已有内容。**对照表落在「速查总览」类笔记里**，并交代材料缺哪几章。

38. **`Read` 图片返回「Content filtered」时，先怀疑裁切长宽比，别急着断定"本模型不能读图"**。本批《信号与系统-拉普拉斯变换》单页手写卡：第一次按 `clip=(60,120,420,150)` 这类 **12:1 细长条** 裁切，主线程 `Read` 全部返回 `does not support images / Content filtered`；改按**常规比例（约 1.4:1～2:1）**分成 7 块（`(10,15,300,130)` 等）后，**同一模型逐块读得清清楚楚**，手写公式全部可靠转录。**做法：被过滤时先「切成接近方形的大块 + 350 DPI」重试一遍**，只有常规比例大块也读不了，才按第 36 条降级（派子代理或凭领域知识重建）。**第一批曾据一次失败就断定"读不了图"、改用领域知识重建 9 页公式，代价是丢了唯一的自证手段——别再这样下结论。**

39. **「文本层乱码」分两型，且偏移扫描的"高命中率"可能是假阳性**。第 35 条是①型（码点整体平移，`+0x4A2C` 能还原中文）。本批是②型：**字体子集 ToUnicode 缺失**（字形按 glyph index 输出），498 字符乱码直接做 `-0x2000～0x8000` 全扫，`off≈19960` 竟给出 **413/498 命中**——**但这是假象**：原文字符码点普遍很低（`U+2237 ∷`、`U+3013 〓`，均 ≤0x3013），加任何 0x4E00 量级的偏移都会把它们整体推进 CJK 区，解码出来仍是 `丂瀯丂縋…`。**判据：偏移命中率再高，也必须把解码后的字符串实际读一遍**（能读出成词的中文才算还原）；原文字符集以低码点为主时，"高命中率"毫无意义。②型只能走视觉转写。


## 扫描件（视觉转写）标准流程（已验证）

当 `extract-text` 返回空/近空（扫描件、无文本层）时，按此流程处理（已在唐迟《词汇的逻辑（第二版）》377 页扫描件上跑通）：

1. **渲染为 PNG**：优先用 PyMuPDF（项目 venv `envs/default/Scripts/python.exe` 已装 `fitz`；托管 python 无 fitz），把 PDF 渲染成 150 DPI PNG 到 `.workbuddy/pdf_pages_<slug>/`，命名 `p001.png`…（页码有序便于引用）；有 poppler 亦可用 `pdftoppm -png -r 150`。**渲染前先确认确实无文本层**：`page.get_text()` 长度为 0 才是纯扫描件；只测头几页不够——正文可能有文本层而附录/答案页没有（郑君里上册 p407 起全书唯一无文本层的一段）。
2. **主模型不能读图时，主线程不要读图**：若 Read 图片返回「does not support images / Content filtered」，改派**子代理**读图转写并**落盘**到 `.workbuddy/extraction<n>/`，主线程只解析文本。
3. **先试内置书签，再谈侦察**：`pymupdf.open(pdf).get_toc()` 若返回完整章/节目录（郑君里《信号与系统》上册 88 条、下册 72 条），就能一次拿全「章节 → PDF 页」映射，**直接省掉侦察子代理**；偏移用「印刷页 = PDF 页 − 常量」反推。**同一套书的不同分册偏移可能不同，必须分册复核**：郑君里上册恒为 16，下册恒为 7（下册 PDF p8 = 书 p1，p50 页眉「习题 43」印证）。**复核手法**：渲染一页带页眉/页脚的图，用「PDF 页号 − 页眉上的印刷页号」直接得常量。**只有确实没有书签时**才派 1 个子代理读封面/目录（前 ~40 页），取到偏移与各章/单元起始页，写临时文件（如 `.workbuddy/scout_result.md`）。注意：章标题页后常紧跟一页**纯二维码/广告页**（无正文，跳过）；目录里章节标题旁的页码是**标题页**而非首个单元页。
4. **并行转写用重叠页段**：按页段分给多个子代理，相邻代理**故意重叠若干页**。**教材类扫描件实测每段 20–28 页、重叠 4–6 页最稳**（55 页用 3 段、93 页用 4 段、附录 32 页用 4 段、下册第七章 43 页用 2 段、第八章 73 页用 4 段、第九章 65 页用 3 段，均一次成功且 `[无法辨认]` 为 0）；小字号密排页（如词汇书）可用每段 ~45–60 页、重叠 ~10 页。**重叠不要少于 3 页**，否则衔接处容易断，也无法互校。子代理只写自己范围内的单元，输出严格结构化文本（见下）。让子代理「先写文件、再返回摘要」；**摘要为空多是文本通道抖动，文件往往已写好 → 用 Glob/Read 核实，勿盲目重跑**。派单时在提示词开头写明「若你不具备图像识别能力，立即只回复 VISION_UNAVAILABLE，不要编造不要写文件」，便于快速识别误路由。
5. **按单元号合并去重，并把重叠区当质量校验用**：解析时按「单元号 → 词群标签 → 单词」三层合并——重叠段/被切断的单元自动拼合；**切勿用「取最完整的一份」策略**（同一单元可能恰好被切在两份转写里：如某单元词群 1 在一份、词群 2 在另一份）。**数值型内容另有两道廉价自检**：① 数学退化（令参数取特殊值，看是否回落到已知的简单结果）；② 总量守恒（如卷积和各值之和 = 两原序列各自和之积：第七章例 7-16 的 `6+5+23+12+21+5 = 72 = 8×9`）。**验算通过的公式才写进笔记**，验证明细记入会话日志。
   **重叠区还是唯一的自证手段**：同一页被两段独立转写，逐条比对即可暴露分歧——单段转写无法自证正确（郑君里上册附录批靠这招抓出 4 处错误，其中 3 处来自同一段，该段的转写者还自述"环境无图像裁剪工具、无法局部放大"）。**分歧一律用 `page.get_pixmap(dpi=420, clip=...)` 局部裁切回原页裁决**，150 DPI 整页在字形相近处（α/a、上标幂次、5/3）容易误读。**公式类内容再做数学退化自检**（令 `n=0`、`a1→a2` 回代，看是否回落到已知的简单结果）——能算出已知结果的公式才算抄对。核对结论写进一篇「导入核对记录」笔记（订正清单 + 知情缺口），别只留在会话日志里。
6. **429 频率限制**：派子代理报 429 时，用 `model:"lite"`（或换模型）重派即可绕过。
7. **渲染缓存可删**：PNG 可由已归档 PDF 完全再生，核对完成后即可删除省空间（若超 ~50 个文件，按安全规范先列清单征得同意）。
8. **公式表/附表类 материала另有一套笔记-卡片设计**（附录、公式手册、答案册都归这类）。此时材料本身不是"概念"而是"结果索引"，**照概念笔记的路子写会和正文笔记大面积重叠**。做法：
   - 笔记按**表**为单位拆（一张速查表一篇，20 行以内可两篇），标题带「速查」；正文放完整表格 + 「使用要点」+「与哪篇正文笔记分工」+ Gaps；按章节的答案册则一章一篇，正文用「题号 → 答案」表，并在 Gaps 里逐章列全**原书未给答案的题号**。
   - 卡片**只对正文笔记未覆盖的条目制卡**（先在标题里扫一遍现有笔记，正文讲过的信号/变换对就别再出卡），优先"退化自检方法""两个易混条目的区别""怎么快速判断"这类**用法类**问题，而不是照抄公式。
   - 材料若本身是**选答/节选**（郑君里习题答案只答部分题），必须在笔记与 Gaps 里写明"原书为选答，对不上答案属正常，不是转写遗漏"——否则用户会误判成导入缺失。
   - 材料若是**覆盖全科**的公式手册（跨多章、与既有笔记大面积重叠），允许**不新建任何概念笔记**：只建 1 篇「速查总览」（含章号对照表）+ 按表拆的若干速查 + 1 篇「导入核对记录」。**并在会话日志里逐章写清「材料内容 → 既有哪篇覆盖 → 处理方式（不建 / 合并 / 新建）」的比对表**，让「为什么一篇概念笔记都没建」有据可查。本批《信号与系统公式全总结》（9 页）即按此办理：材料概念性内容 100% 已被既有 485 篇覆盖，最终只产出 8 篇速查 + 1 篇核对记录 / 27 张卡；卡片全部做「用法/辨析」类（跨章对照怎么用、两个易混条目的差别、材料内部两处写法为何不一致），不照抄公式。
   - 判断"某概念是否已被覆盖"时，**先导出全主题 `order/id/title/tags` 表与全主题卡片题面表**（`list_<slug>_notes.py` / `list_<slug>_cards.py` 落盘成 txt），再用 `grep -iE "关键词1|关键词2"` 批量比对；比逐篇读笔记快得多，也能顺带发现"卡片题面是否会撞车"。

**转写文本格式**（下游解析器依赖，必须一致）：

```
# Unit NN 名称

词汇数量：X   词群数量：Y
词群逻辑：……

## 词群N：组名
- word  [音标] 词性. 释义
  - 派生：……
  - 拓展：……
  - 考点：……（年份）……
  - 例句：English sentence.  中文译文。
  - 文化：……
```

单词为顶层 `- ` 项目；派生/拓展/考点/例句/文化/辨析/搭配/用法为**缩进两空格**的 `  - ` 子项。解析器据此还原「词群逻辑表 + 逐字原句」，再按第 6 步批量制卡。
