# 错题录入（W9）

**角色**：先读 `roles/librarian.md` 并全程保持「导入员」人格（忠实提取、宁可少而准、绝不编造）。同时遵守仓库根目录 `AGENTS.md` 的数据契约（「错题」小节的 frontmatter 格式以那里为准）。

错题的价值不在"存下来"，而在"搞懂 + 不再错"。每条错题必须带分析，不许只存题目和答案。

## 步骤

1. **收图存挡**：用户发来的每张错题图片，先保存原图到 `data/mistakes/assets/<错题id>.<原扩展名>`（id 建议 `YYYYMMDD-image-<topic>-<n>`，kebab-case 全局唯一）。**题目图、答案/解析图等全部留档**——多图分别命名 `<id>.png`、`<id>-a.png`…，全部列入错题的 `images` 列表字段（单图可只用 `image` 字段）。原图是日后对照的凭据——绝不只解析不留档。
2. **逐题解析**：视觉读取题目原文、正确答案、（若图中可见）学习者的错误作答。一张图可能有多题，逐题拆分；解析不清的题如实报告并跳过，**绝不编造题目或答案**。
3. **确认 topic**：错题主题必须同学习主题一致——先列出 `data/topics/` 下现有主题与用户确认归属，**复用现有 slug，不自造近似主题**；只有用户明确要新建主题时才建 `data/topics/<slug>/manifest.json`。
4. **知识点判定**：指出每题考察的知识点/考点，`knowledge` 只填**短概念名（≤20 字，如"拉格朗日配方法"，不写描述句）**；掌握要点的提醒放在口头回复与 `solution`/`analysis` 里，不塞进 `knowledge`。
5. **解题分析**：
   - `solution`：解题思路分析（从哪入手、关键步骤、为什么这么做）；
   - `hint`：15-40 字重练提示，只给思考方向或关键词，**不复述答案**；
   - **选择题必须写 `option_analysis`**：逐选项说明为什么能选、为什么不能选；非选择题该字段留空字符串；
   - `pitfalls`：易错点分析（这类题最常见的坑、和本题错因的关系）。
6. **联网检索同考点真题**：用网页搜索（WebSearch/FetchURL 等你可用的能力）查找权威考试真题或高质量模拟题中考查**同一考点**的题目，填 `related` 列表（title/url/source/note；note 写明官方答案或权威解析要点）。纪律：
   - **必须是真实可访问的出处链接**（官方考试机构、权威出版社/题库），最好能打开核验；
   - 找不到可靠来源就如实告知用户，填 `related: []`，**禁止编造链接、题号或答案**；
   - 用户环境无联网能力时同样如实说明并留空。
7. **去重**：与 `data/mistakes/` 现有错题逐一比对——同题不重复录入；有增量（更准的解析、新真题链接）就补充进现有文件正文或相关字段（**不动 `status`/`mastered_at`**，那是服务端的）。
8. **落盘**：每题写一条 `data/mistakes/<id>.md`，frontmatter 按 AGENTS.md「错题」小节（`source: image`、`session: ""`、`status: active`、`mastered_at: null`、`image: assets/<文件名>`）。
9. **收尾自检（必须）**：`curl -s http://127.0.0.1:5574/api/validate`，errors 清零后才算完成（image 指向的原图必须存在）。向用户报告：新建/更新了哪些错题文件与原图、related 检索到了几条真实出处、提醒去 Web UI「错题库」页重练。

## 禁止

- 只存题目和答案、省略 knowledge/solution/pitfalls 分析；
- 选择题不写逐选项分析；
- 编造 related 链接、题目出处或官方答案；
- 改动 `status`/`mastered_at`（服务端经 UI 独占）；
- 删除任何错题文件或原图。
